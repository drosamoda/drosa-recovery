# Campaign Studio Creative Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn existing campaign opportunities and drafts into a non-dispatching Campaign Studio that produces copy variants and persistent image assets tied to verified Product Truth, with human fidelity approval.

**Architecture:** Extend the existing `CampaignDraft`/AI strategy pipeline rather than creating a parallel campaign system. Keep text strategies in draft JSON, add a dedicated `CampaignCreativeAsset` table for image lifecycle, use a provider adapter for image generation, and store generated bytes in private Google Cloud Storage. Generation never sends email or WhatsApp.

**Tech Stack:** TypeScript, Prisma, existing AI provider pipeline, OpenAI image adapter, Google Cloud Storage, Express, React, TanStack Query.

**Spec:** `docs/superpowers/specs/2026-09-28-drosa-central-campaign-studio-design.md`

## Global Constraints

- Exactly three strategic directions A/B/C remain.
- Each email strategy supplies five subject options total and three preheader options total.
- Product-specific image generation requires a verified Product Truth record with a real reference image.
- Generated assets default to `PENDING` fidelity and cannot auto-approve themselves.
- Private draft assets must not use Cloud Run filesystem as durable storage.
- Image generation is disabled by default unless provider and bucket are configured.
- No send or scheduling path is added in this plan.

## Review Focus

1. Product-specific generation with missing/failed Product Truth must fail before any paid image call.
2. Retrying the same asset-generation action with the same idempotency key must not create/pay twice.
3. An asset from another draft must never be selectable or reviewable under the current draft.
4. A generated image remains non-publishable until a human marks fidelity PASS.
5. Provider errors must persist closed categories, never raw provider payloads or prompts containing sensitive data.
